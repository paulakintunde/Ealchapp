## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] author-narration-batch.ts never bumped lesson.version, unlike its seed twin**
- **Found during:** Task 3, step 2 (`pnpm content:parity` after the first `author-narration-batch.ts` run)
- **Issue:** `apply-narration-seed.ts` sets `version: (lesson.version ?? 1) + 1` when it adds narration to a lesson in the seed; `author-narration-batch.ts` added the same `narration` and `features` fields to the Postgres copy but left `version` untouched. After the first (unfixed) run, all 30 lessons still showed as SHAPE DRIFT in `content:parity` — same magnitude of drift as before the write, just carried entirely by the version number now that content otherwise matched
- **Fix:** Added `version: (lesson.version ?? 1) + 1` to the script's normal write path (matching the seed twin exactly), plus a self-healing branch: if a lesson already has narration in Postgres and its version is exactly one behind the working-tree seed's version for that id, the script now bumps it to match instead of silently skipping. Ran the fixed script again (dry run first, confirmed all 30 would heal, then for real) to repair the 30 rows the earlier buggy run had already written
- **Files modified:** `ealch-admin/scripts/author-narration-batch.ts`
- **Verification:** `pnpm content:parity` now exits 0 with no SHAPE DRIFT or seed-only lines; `_publish_blockers.ts` confirms nothing would be destroyed
- **Committed in:** `e5ec34e` (part of the Task 3 commit — the script was already in this task's approved `<files>` list)
