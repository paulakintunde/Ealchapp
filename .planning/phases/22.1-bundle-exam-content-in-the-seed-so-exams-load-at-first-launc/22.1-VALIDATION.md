## Method corrections found while running plan 08

**1. `cmd connectivity airplane-mode enable` does not make this device offline.**
With airplane mode reported ON (`airplane_mode_on=1`), `dumpsys connectivity` still
showed `WIFI CONNECTED ... VALIDATED` on SSID SHAW-6AE5 and `ping 8.8.8.8` returned
0% packet loss. Android keeps Wi-Fi up inside airplane mode when Wi-Fi was on
beforehand. Had the app been launched in that state it would have downloaded the v73
snapshot and the "seed-only" proof would have measured the snapshot path instead.
`svc wifi disable` + `svc data disable` is the real offline, and it must be verified
with `ping`, not with the airplane-mode flag.

*Applies retroactively to plan 06's baseline row*, which used the airplane-mode command
alone. Its conclusion survives (exams published at v71 on 2026-09-23, a day after that
run, so no snapshot then available could have carried papers) but the isolation it
claimed was not established by its method.

**2. A bare `ealch://exam` proves nothing about exam content.**
`app/exam.tsx:61` reads a `format` query param; `exam.tsx:82` computes
`papers = format ? examPapersFor(corpus, format) : []`. With no `format`, the list is
empty and `examNoPapersYet` ("No exams available yet.") renders **regardless of how much
exam content is loaded**. Demonstrated directly: on the pre-wipe build, bare
`ealch://exam` showed "No exams available yet." while `ealch://exam?format=tef_canada`
on the same running instance listed all five TEF papers.

*Applies retroactively to plan 06's baseline row*, which cites that string as
confirming "0 exam papers". The claim was true, but this evidence cannot establish it.
The after-pass uses `ealch://exam?format=<tef_canada|delf_b2|tcf_canada>`.

**3. A dozing screen silently voids `am start -W` timing.**
The first 8-run attempt returned `LaunchState: UNKNOWN (0)` and no `TotalTime` at all
(only `WaitTime`), and every screenshot was pure black with no status bar. Cause:
`mWakefulness=Dozing`. `TotalTime` is reported when the first frame is drawn, and
nothing draws with the display asleep. Fix: `input keyevent KEYCODE_WAKEUP` before each
run plus `svc power stayon usb`. All 8 re-runs then reported `COLD`.

**4. `uiautomator dump /sdcard/ui.xml` needs `MSYS_NO_PATHCONV=1`** under Git Bash on
Windows, or the path is rewritten to `C:/Program Files/Git/sdcard/ui.xml`.

carry state that keeps the radio up.

### A note on the metric itself

`TotalTime` was assumed to measure only the native splash. It does not: `Displayed` fires
**after** `Running "main"` (+269ms vs +1345ms on an onboarded launch), so JS bundle
evaluation and first render are inside the number. The metric is measuring the right
thing — but it is dominated by *which screen the app lands on*, so before/after runs must
be in the same account state or the comparison is meaningless.
