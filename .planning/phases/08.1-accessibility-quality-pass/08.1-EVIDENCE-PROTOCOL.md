# Phase 08.1 evidence protocol

Every plan in this phase ends in a **stage gate**. A gate is closed only by rows in `08.1-DEVICE-EVIDENCE.md` in the format below, never by a summary sentence. This implements D-22.

## Before every plan

1. Check the working tree. Run `git status --short -- <every path in files_modified>`. If a path carries someone else's uncommitted edits (Phase 9, C1 content), stop and report. Do not stash, revert or check out.
2. Do not search the whole disk (`find /`). Stay inside the repository.

## Automated gate (every plan, not just the last)

From `ealch-v2/`:

```
npm run typecheck
npm test
npm run test:component -- --runInBand --silent
```

All three must exit 0, or every failure must be shown to pre-exist on `HEAD` before the plan's first commit. To show that, record the failing test names and prove they fail at the parent commit by running them in a separate `git worktree`. Never stash in this shared tree. A failure the plan introduced blocks the plan. Do not weaken a legacy test to make it pass. If a legacy assertion encodes behaviour a locked decision changed, cite the decision ID in the commit message.

## Commits

- Use the scope `08.1-NN` on every commit, for example `fix(08.1-02): resolve Automatic from the OS scheme`. One commit per task.
- Commit with `git commit --only -- <paths>`, because the index is shared with concurrent sessions.
- New `.md` files need `git add -f`, because `*.md` is gitignored.

## Which build (dev for fixing, preview for results)

A gate row counts only if it was recorded on a **preview build**: EAS profile `preview`, channel `preview`, release JS, no dev client. The dev build is for finding and fixing problems inside a stage; rows recorded on it are working notes, not results. Why:
- the dev client reconnects to Metro when the activity is recreated, which confounds the live font-scale test (D-20);
- dev overlays (LogBox, dev menu, launcher) enter the TalkBack order;
- the dev build has no packs layer (published B1/B2 lessons are untappable) and its content cache can outrank the seed;
- in dev, the paywall shows "Purchases are not available in this build";
- E1 is a timing problem, and release JS changes timing.

How a stage reaches the preview build:
- **Native change** (config plugin, native module): a new binary, built in the EAS cloud with `eas build -p android --profile preview`. Local `gradlew assembleRelease` is blocked by the reanimated Ninja failure. Never ship native changes by OTA.
- **JS-only change**: the runtime policy is `fingerprint` (`app.json`), so run `npx @expo/fingerprint .` before and after the stage's commits and confirm the hash is unchanged against the installed preview binary's runtime version. Then `eas update --channel preview`, and confirm on the device that the update is running (update id in the row's Build column). Check that the bundle carries the EAS `preview` environment variables, by grepping the `.hbc` as described in the `ealch-eas-update-drops-env` memory.

The Build column records: `preview`, the EAS build id (or update id), and `git rev-parse --short HEAD`.

## Device row format (`08.1-DEVICE-EVIDENCE.md`)

| Stage | Screen | Control or check | Verbatim TalkBack utterance | Activation outcome | Focus after | Account | Font scale / display size | Build | Result |
|---|---|---|---|---|---|---|---|---|---|

Rules:
- **Verbatim** means exactly what TalkBack said. Turn on TalkBack's developer setting "Display speech output" (or use "Copy last utterance") and paste it in; do not paraphrase. A row without an utterance is not a pass for a screen-reader check.
- For non-screen-reader checks (theme, font scale), put the observed state in the utterance column, for example `cmd uimode night = no; Settings shows AUTOMATIC · LIGHT; palette light`.
- **Account** is `free` or `premium`. Locked-content rows must be `free`.
- **Build** follows "Which build" above. A row whose build is not `preview` is not a result.
- **Result** is `pass`, or `fail → fixed in <sha> → pass`. `Pending`, `partial` and `user-reported` are not results. A gate with any row not ending in `pass` stays open.
- A failure found at a gate is fixed inside the same plan and re-tested in a new row. Do not move it to a later stage.

## Device setup reminders

- Use the USB Pixel 6, never `--localhost`. If the dev client will not connect, see the `ealch-usb-metro-dev`, `ealch-manifest-retry-pileup` and `ealch-adb-reverse-lies` memories.
- Deep-link straight to a screen with `adb shell am start -d "ealch://..."` (see the `ealch-device-deep-link` memory).
- Font scale: `adb shell settings put system font_scale 1.3`. Theme: `adb shell cmd uimode night yes|no`.
- After the stage, restore the original font scale, theme, and TalkBack state, and record that you did.

## Gate approval

At each `checkpoint:human-verify`, the executor prepares the device, lists the exact rows to fill, and waits. The resume signal is the filled rows themselves, not the word "approved". The executor then checks every row against these rules before closing the plan.
