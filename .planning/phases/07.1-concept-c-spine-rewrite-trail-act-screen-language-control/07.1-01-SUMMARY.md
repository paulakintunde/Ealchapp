## Decisions Made

- **Board C4 disposition (D-31):** accepted as indicative, not redrawn. sons.01 was built to the board's own six-act count; the act boundaries and copy are this build's own, not a transcription of the board's placeholder labels.
- **D-25 (version-bump guard ignored, explicitly):** `pnpm content:versions` was run at the checkpoint and, as expected, demanded a bump on all four lessons (its `sectionIds()` comparator treats "section ids went from absent to present" as a structural change, even though the section *count* held). This is the exact guard D-25 says to ignore: bumping would key `lessonMissions[id].v` (`app/missions.tsx`) to a new value and silently zero every learner's stored checkmarks and lesson XP for these four lessons. Recorded output:
  ```
  4 lesson body/bodies changed since HEAD
    correct                             0
    bumped for a TEXT-ONLY edit         0
    section list changed, version held  4
  ✖ SECTION LIST CHANGED AND THE VERSION HELD. Stored indexes now point at the wrong missions:
      sons.04.l1   v2 -> v2   sections 21 -> 21
      sons.01.l1   v3 -> v3   sections 26 -> 26
      sons.03.l1   v5 -> v5   sections 20 -> 20
      sons.02.l1   v5 -> v5   sections 20 -> 20
  ```
  No version was changed. Both `author-sons-acts-batch.ts` and `merge-sons-acts-into-seed.ts` assert `body.version` is unchanged and refuse otherwise, so this is enforced by the build, not merely by policy.
- **Task split for atomic commits:** the executor split the single module file into two commits (Task 1: sons.01/sons.04 only, with the export type narrowed to those two keys; Task 2: widened the type and added sons.02/sons.03) to match the plan's stated task boundary ("This task authors ONLY these two... Task 2 adds the journey-shaped pair") rather than writing all four lessons in one commit.
