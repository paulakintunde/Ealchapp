Extend the committed two-state English toggle to the three states D-13 approved, without breaking the one rule the control has always had: answers are not glosses and never hide.

Purpose: the two-state version landed as `0b6a1a9` and was proven on hardware in plan 02, which is the whole point of D-17's sequencing. What does need care is three things nobody would catch in review: the migration mapping, `Type.tsx` having no tap target to reveal into, and `MissionRich` reading the context directly and bypassing `TX` entirely.
Output: a three-valued context, a v6 to v7 store migration with a round-trip test, a real reveal affordance, the panel wired into the lesson header on B1+ only, and the D-16 guard that never existed.
</objective>

<three_ways_this_ships_broken_and_green>
From the research, verbatim, because each is invisible in code review:

1. **Forgetting to add `lessonEnglishMode` to `partialize`** — it will not persist, silently. Works in a session, resets after force-stop.
2. **Forgetting to remove `lessonEnglish` from `partialize`** — the dead key keeps being written and the two can disagree.
3. **Mapping `true` to `'onDemand'`.** Today's `true` prints the translation under every line. That is **`'both'`**. This is the one that gets shipped.

And a fourth, from `GlossContext.tsx:4-5`: *"Defaults to TRUE: only the lesson screen provides a value, so every other screen renders its English exactly as before."* Twelve of the thirteen `gloss` call sites are in components that **also render outside a lesson** (flashcards, roleplay, review, smartreview). **The new default must be `'both'`**, or English silently disappears from six other screens.
</three_ways_this_ships_broken_and_green>

<decisions_this_plan_makes>
**D-35, the tap target.** `Type.tsx:137` is `if (gloss && !showEnglish) return null;` on a pure `<Text>` with no press handling, so "anglais a la demande" has no tap target today. **Resolution: `TX` grows a reveal affordance only on the `gloss && mode === 'onDemand'` branch** — the gloss renders as a small tappable placeholder that swaps to the translation on press, with local state in `Type.tsx`. Every other branch renders a bare `<Text>` exactly as now. `TX` is used everywhere; this must not make it a `Pressable` in general.

**D-35, the `EN:` tail.** `Type.tsx:141-153` handles a translation that is **inline inside a string**, so the naive tap target is a sentence fragment. **Resolution: in `onDemand`, render `stripEnTail(children)` plus the reveal affordance as a SEPARATE trailing element**, never as a press handler on a substring. The tail already renders as its own `<Text key="en">` element in the `showEnglish` branch, so there is an element to hang it on.

**D-35, `MissionRich`.** **Resolution: thread `useEnglishMode()` into `MissionRich` and give the `respell . en` cell a reveal in `onDemand`.** If that cell genuinely has no place for a press affordance in its layout, fall back to keeping the English visible there, **record it in the SUMMARY as a scoped exception with the reason**, and plan 11 puts the group drill in front of Paul on the device in on-demand mode. Do not silently pick the fallback.
</decisions_this_plan_makes>
