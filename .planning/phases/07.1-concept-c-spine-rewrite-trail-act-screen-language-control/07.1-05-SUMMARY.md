## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Correctness] Two D-44 violations found while writing the source guard**
- **Found during:** Task 3, writing `spine-routes.test.ts`'s height-on-text scan.
- **Issue:** `act.tsx`'s "Ecouter l'ouverture" chip (`height: 37`) and `fiche.tsx`'s primary CTA (`height: 54`) both used a bare `height:` on a button wrapping a `<TX>` label — ported verbatim from `missions.tsx`/`lessonoverview.tsx`, which predate the D-44 rule (a fixed `height:` on text-bearing UI can clip a line's tail at font scale 1.3, D-38 defect 3's exact shape).
- **Fix:** Changed both to `minHeight:`, matching the precedent `subMission.logic.test.ts:432-437` already documents for `ReadingPages.tsx`'s own listen button ("legitimately uses minHeight for its tap target"). No visual change at default font scale; the button can now grow instead of clipping at 1.3.
- **Files modified:** `ealch-v2/app/act.tsx`, `ealch-v2/app/fiche.tsx`
- **Verification:** `spine-routes.test.ts`'s D-44 test passes; `npm run typecheck` and `npm test` both green.
- **Committed in:** `2caf739` (Task 3, alongside the test that caught it)

### Documented, not fixed — several Task 2 acceptance-criteria grep counts are unsatisfiable as literally written

- **Found during:** Task 2 verification.
- **Issue:** Four of Task 2's literal `grep -c` acceptance criteria expect exactly 1 occurrence of a name that is both imported and called once (`useFocusEffect` = 1, `releaseLine` = 1, `lessonEyebrow` = 1) or expect exactly 2 occurrences of `audio.stop()` where the verbatim-reuse instruction for the intro-listen chip (interfaces block, "Reuse verbatim from app/missions.tsx... the inline listen chip :53-62") itself contains a third `audio.stop()` call. A normal `import { x } from 'y'; … x(…)` pair always produces 2 source lines containing the name, and `missions.tsx` itself — the file these criteria are modeled on — has the identical shape (`useFocusEffect` = 2, `audio.stop()` = 3 there too, confirmed by inspection). This is the same class of grep-literal mismatch 07.1-04-SUMMARY.md documented for `trackLabels`.
- **Resolution:** Verified the criteria's actual INTENT instead: both teardowns exist (`useEffect` cleanup + `useFocusEffect` cleanup), `releaseLine` is called exactly once with no second implementation authored, `lessonEyebrow` is called exactly once matching `missions.tsx`'s own header shape, and the intro-listen chip's `audio.stop()` call (interrupting any playback before starting a new one) is functionally required and explicitly named in the plan's own reuse instructions. One genuinely fixable case — `rec.v === L.version` appearing twice (once each for `done` and `xp`) — WAS fixed, by factoring the version-guard check into a single `validRec` binding, bringing that one criterion's count to the literal 1 without any functional change.
- **Files affected:** `ealch-v2/app/act.tsx` (the `validRec` refactor only; no other code changes for this item)

**Total deviations:** 2 (1 auto-fixed, 1 documented-not-fixed literal-grep mismatch affecting 4 criteria)
**Impact on plan:** No scope creep, no behavioural gaps. The D-44 fix is a real, if small, robustness improvement over the ported originals.
