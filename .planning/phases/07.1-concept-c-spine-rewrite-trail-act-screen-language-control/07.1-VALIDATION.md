# Phase 07.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Opened by plan 02,
> appended by later plans, closed by plan 11.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Node built-in test runner (`node --test`) in `ealch-v2`; Jest (`jest-expo` + React Native Testing Library) for component tests, also in `ealch-v2`; `ealch-admin` uses `node --import tsx --test` where its scripts are touched |
| **Config file** | none for `node --test` — `ealch-v2/package.json` `test` glob; `jest.config.js` for `test:component` (deliberately omits `<rootDir>` on `testMatch`, see jest.config.js:12-17) |
| **Quick run command** | `cd ealch-v2 && node --test src/store/bandFallback.test.ts` (or any single new/edited test file) |
| **Full suite command** | `cd ealch-v2 && npm test` (node --test, ~90s) ; `cd ealch-v2 && npm run test:component` (Jest, ~5-6min) |
| **Estimated runtime** | ~90s (`npm test`) + ~5-6min (`npm run test:component`) |

---

## Sampling Rate

- **After every task commit:** targeted `node --test` on the new/edited file
- **After every plan wave:** full suite (`npm test` + `npm run test:component`) in `ealch-v2`
- **Before `/gsd-verify-work`:** full suite green, device pass recorded for every `D-*`/`A*` claim this phase's objective rests on
- **Max feedback latency:** 120 seconds (targeted); full suites exceed this and are run at task/wave boundaries only, per house pattern (see 22.1-VALIDATION.md)
