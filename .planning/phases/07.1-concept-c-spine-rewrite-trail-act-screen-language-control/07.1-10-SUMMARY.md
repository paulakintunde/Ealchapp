## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `dayOne.test.ts`'s own key-set diff was self-referential and went red the moment its own GREEN commit landed**
- **Found during:** Task 3, running the full `npm test` suite (the plan's own "after every plan wave: full suite" sampling rule).
- **Issue:** The first draft of the "partialize gained exactly these two keys" test (Task 1) diffed the current `useStore.ts` against `git show HEAD:.../useStore.ts` to find the pre-plan baseline. This works only as long as `HEAD` still points at a commit from BEFORE this plan's own `partialize` addition. The moment Task 1's GREEN commit (`f3ea1c8`) became `HEAD`, `git show HEAD:...` started returning the file WITH the two new keys already present, so `gained` computed as `[]` instead of the two expected keys — the test failed, self-inflicted, on the very next full-suite run (caught immediately, not deferred).
- **Fix:** Replaced the `git show HEAD` read with a fixed, in-file baseline array (`PRE_PLAN10_PARTIALIZE_KEYS`, the 28 keys `partialize` carried before this plan, copied from the pre-plan source) — a baseline that does not move as the branch gains commits, so the test remains a real regression guard for as long as it exists in the repo, not just for the lifetime of this plan's own HEAD position.
- **Files modified:** `ealch-v2/src/store/dayOne.test.ts`
- **Verification:** `node --test src/store/dayOne.test.ts` — 7/7 pass, including the key-set diff test, confirmed stable across the Task 3 commit (which itself changed `HEAD` again, with no effect on this test now).
- **Committed in:** `ed39054` (Task 3 commit)

### Documented, not fixed — two acceptance-criteria grep literals are unsatisfiable as literally written

- **Found during:** Task 3 verification.
- **Issue:** `grep -c "useReduceMotion" ealch-v2/src/components/TrailRow.tsx` = 1 and `grep -c "resumeIsFresh" ealch-v2/app/den.tsx` = 1 are both stated acceptance criteria. - **Resolution:** Verified the criteria's actual intent instead: `useReduceMotion` is imported once and called once, with no second implementation; `resumeIsFresh` likewise, already correct since plan 08. Not a code change beyond the one comment reword.
