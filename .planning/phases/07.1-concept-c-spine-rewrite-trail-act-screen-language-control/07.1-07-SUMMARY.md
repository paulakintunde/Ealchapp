## Store migration shape

```
v6: { lessonEnglish: boolean }              // default false
                    |
                    v   migrateLessonEnglishMode()
v7: { lessonEnglishMode: 'fr' | 'both' | 'onDemand' }   // default 'fr'
```

- `true` → `'both'` ("Français et anglais" — translation printed under every line; this is the direction that ships broken if reversed)
- `false` or missing → `'fr'` (the old default)
- `'onDemand'` has no old value; nothing in the ladder ever assigns it
- `partialize` persists `lessonEnglishMode`, no longer persists `lessonEnglish`
- Verified in `englishMode.test.ts` (9 tests: a real round trip through `migrateLessonEnglishMode`, source-guard confirmation of the AppState field/default/setter/version/ladder-step/partialize-keys, and every pre-existing v0→v6 ladder step confirmed unchanged) plus `english.logic.test.ts`'s own direct value-pinned tests of the mapping function.

## Issues Encountered

- `grep -c "useEnglishMode" Type.tsx` / `grep -c "glossToggleApplies" lesson.tsx` = 2, not 1 — one line is the import statement, the other is the call site; `grep -c` counts matching LINES, and any hook/function that is imported AND called inherently produces 2, not 1.
