    - `email`, `answer` and `transcript` at top level or inside context never appear in the JSON output.
    - details: 1500 chars → 1000; whitespace-only → null. screen 'Exam Report!' → null, and the rest of the payload is kept.
    - 14 errors → last 10; message 900 → 300; stack 4000 → 1500; missing stack → null.
    - font_scale 9 → null; theme 'blue' → null; platform 'windows' → 'web'.
    - Worst-case input → JSON ≤ 24576 bytes. Every built payload satisfies `validateWire(p).ok === true`.
    validateWire(body) → { ok: true } | { ok: false; field }: strict, same rules as the server. Unknown or extra key → that key's name; unknown context key → 'context.<key>'; a non-object body → 'body'.
    classifySend: 200/201 → sent; 'offline', 408, 429, 500, 503 → retry; 400, 401, 403, 413, 422 → drop.
    outcomeFor: 'offline' → queued-offline; 429 → queued-limited; 408 or 5xx → queued-busy; 2xx → sent; other 4xx → rejected.
    nextUtcDay(Date.UTC(2026,9,1,23,30)) → Date.UTC(2026,9,2,0,0).
    Outbox entries are `{ payload: ReportPayload; notBefore: number | null }`. REPORT_OUTBOX_LIMIT = 20, REPORT_OUTBOX_MAX_AGE_MS = 30 days.
    - claimReport(outbox, payload, now): appends with notBefore null; the same report_id is not added twice; when full, the oldest entry is evicted (the learner's newest report wins); prunes expired entries.
    - settleReport(outbox, report_id, status, now): sent or drop → entry removed; retry and status 429 → notBefore = nextUtcDay(now); other retry → notBefore null.
    - dueReports(outbox, now) → entries with notBefore null or ≤ now, in order.
    - validReportOutbox(garbage) → []; invalid entries are dropped by rebuilding each payload through buildReportPayload.
  </behavior>
