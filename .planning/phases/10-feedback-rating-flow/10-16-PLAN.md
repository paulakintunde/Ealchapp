<feature>
  <name>Report item keys for quiz questions and mission cards</name>
  <files>ealch-v2/src/content/quizItemKey.logic.ts, ealch-v2/src/content/quizItemKey.test.ts</files>
  <behavior>
    - hash8('') is the FNV-1a offset basis as 8 hex characters ('811c9dc5'); the output is always /^[0-9a-f]{8}$/.
    - quizItemKey('a1.04.l1', q, null, 3) → 'a1.04.l1#quiz.q3:h' + 8 hex characters; quizItemKey('a1.04.l1', q, 'r2', 0) → 'a1.04.l1#quiz.r2.q0:h' + 8 hex characters.
    - Reordering q.opts with the same correct option TEXT (correct index updated to match) gives the SAME key.
    - Changing q.q text, or the correct answer text, gives a DIFFERENT key.
    - Whitespace or Unicode-normalisation-only differences in q (NFC versus NFD, double spaces) give the SAME key.
    - missionItemKey('a1.04.l1', 's3', 2) → 'a1.04.l1#s3.c2'; a null sub → '.c1'. Characters outside [A-Za-z0-9._-] in the section id are replaced with '-'.
    - Corpus: for every lesson in seed.json (and seed-packs.json if present), every quiz question key (flat and rounds) and every section's missionItemKey(id, sub 1) matches /^[A-Za-z0-9._#:-]{1,120}$/, and no two FULL keys in the same lesson are equal (position is part of the key). hash8 equality between two questions of one lesson is allowed only for pairs in `KNOWN_DUPLICATES = [{ lesson: 'c2.04.l1', a: 'q4', b: 'q61' }]`, and for each listed pair the test asserts the two canonical strings are identical (a listed pair with different text fails the test). Any unlisted hash8 equality within a lesson whose canonical texts DIFFER (a true collision) fails the test. A listed lesson missing from the corpus is skipped with a printed note. The test prints the live total question count and the longest key length.
  </behavior>
  <implementation>
    Zero imports. FNV-1a 32-bit: `h = 0x811c9dc5`; for each UTF-16 code unit of `str.normalize('NFC')`, `h ^= c; h = Math.imul(h, 0x01000193) >>> 0`. Output `h.toString(16).padStart(8, '0')`. (Hashing UTF-16 units is deterministic and fine here: the key needs to be stable, not portable to other languages.)
    Canonical string: `[format ?? '', norm(q), norm(prompt), norm(say), norm(word), norm(correctText)].join('|')`, where `norm = (s) => (s ?? '').normalize('NFC').replace(/\s+/g, ' ').trim()`. correctText is: for a numeric `correct` with `opts`, `opts[correct]`; for a string `correct`, that string; otherwise `answer ?? accept?.[0] ?? ''`.
    The test reads the seed with fs and walks lessons → sections → the quiz section's questions (and `rounds[].questions`), matching how `quizQuestions()` flattens. Import that helper if it is pure and node-resolvable; otherwise reimplement the walk and note it.
    RED, then GREEN commits.
  </implementation>
</feature>
