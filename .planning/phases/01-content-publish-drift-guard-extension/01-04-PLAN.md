<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → live Postgres + Supabase Storage | This plan runs the real pipeline in `--dry-run` mode only. `--dry-run` returns before step 8 (upload), step 9 (seed.json write) and step 10 (version counter insert), so no OTA artifact, no `seed.json` rewrite and no version burn can occur. |
| Ops Console operator → `content_units.status` | The block proof flips one scenario's status and flips it back. Reversible, scoped to one row, and no learner is affected because nothing is published during the window. |

Per 01-RESEARCH.md's Security Domain section, ASVS V2/V3/V4/V6 remain not applicable to this surface. This plan adds no code paths, only exercises existing ones.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-08 | Tampering | The verification procedure itself mutating shipped content | mitigate | Every run in this plan uses `--dry-run`, which returns before the upload, the `seed.json` write and the `content_snapshots` insert. Step C restores the unpublished scenario before the phase closes, and Step C's clean re-run is itself the proof that the restore took. |
| T-01-09 | Denial of Service (learner-facing) | Unpublishing a scenario leaves it missing from a later real publish | mitigate | The scenario is re-published in Step C, and Step C's dry-run must come back clean — a still-unpublished scenario would be reported as a loss by the very guard under test, so this cannot pass unnoticed. |
| T-01-10 | Information disclosure | The committed `PUBLISH-REPORT.md` exposing environment detail | accept | Carried from plan 03: `formatDiffReport` is pure and reads no `process.env`; the file holds counts, versions, byte lengths and two digests only. No credentials, storage URLs or learner data can reach it. |
| T-01-01 | Repudiation | A future silent bypass of the drift guard | mitigate | Carried forward from plans 01-03: no bypass flag exists anywhere in the publish path; any future one must log the specific kind and id it overrides. This plan adds no flag and no code. |
</threat_model>
