```typescript
export const DRAFT_VERSION = 1;
/** D-02: long-form typing checkpoints this long after the last keystroke. */
export const DRAFT_DEBOUNCE_MS = 1500;

export type DraftSpoken = {
  transcript: string;
  unavailable: boolean;
  signals: DeliverySignals;
};

export type ExamDraft = {
  v: number;
  paperId: string;
  skill: string;
  savedAt: number;
  answers: Record<string, Record<string, number | null>>;
  texts: Record<string, string>;
  spoken: Record<string, DraftSpoken>;
  coverage: Record<string, Coverage>;
  debate: Record<string, DebateReport>;
  /** Task ids already graded IN THIS SITTING. */
  graded: string[];
};

export function draftKey(paperId: string, skill: string): string;
export function buildDraft(input: {
  paperId: string; skill: string;
  answers: Record<string, Record<string, number | null>>;
  texts: Record<string, string>;
  spoken: Record<string, SpokenAnswer>;
  coverage: Record<string, Coverage>;
  debate: Record<string, DebateReport>;
  graded: string[];
  now?: number;
}): ExamDraft;
export function serializeDraft(d: ExamDraft): string;
export function parseDraft(raw: string | null, paperId: string, skill: string): ExamDraft | null;
export function restoreState(d: ExamDraft): {
  answers: Record<string, Record<string, number | null>>;
  texts: Record<string, string>;
  spoken: Record<string, SpokenAnswer>;
  coverage: Record<string, Coverage>;
  debate: Record<string, DebateReport>;
};
export function isGraded(d: ExamDraft | null, taskId: string): boolean;
export function markGraded(d: ExamDraft, taskId: string): ExamDraft;
export function hasContent(d: ExamDraft): boolean;
```

Implementation rules, all concrete:

- **Imports: type-only, relative, no `@/` alias.** Exactly three:
  `import type { SpokenAnswer } from '../components/ExamSpeakTask';`
  `import type { DeliverySignals } from '../utils/deliverySignals.logic';`
  `import type { Coverage } from '../utils/interlocutor.logic';`
  `import type { DebateReport } from '../utils/debate.logic';`
  (four lines; all `import type`, all erased at runtime). No runtime import of any kind — this file must run under `node --test` with no bundler.

- **`draftKey`** returns the template literal `` `exam-draft:${paperId}:${skill}` ``. **Do NOT use an `attemptId`.** CONTEXT.md D-07's prose says "scoped to the `exam_attempts` row id (e.g. `exam-draft:{attemptId}`)" — that column does not exist. `exam_attempts`' primary key is the composite `(user_id, paper_id, skill)` (`ealch-v2/supabase/schema.sql` lines 417-435). `paperId` and `skill` are both already destructured from `useLocalSearchParams` in `exam-section.tsx` at lines 72-74. `mode` is deliberately excluded, mirroring `exam_attempts`' own PK. Put a comment in the file saying exactly this, citing the schema line range, so nobody re-derives the wrong key from CONTEXT.md later.

- **`buildDraft` is where D-09 is enforced.** For each entry of `spoken`, write `{ transcript, unavailable, signals }` and drop `audioUri` entirely — do not write `audioUri: null`, do not write the key at all. Comment why: the STT device-cache WAV is not guaranteed to survive a process death, so persisting its path would promise a recovery the app cannot deliver. `signals` IS persisted (it is measured evidence, six numbers at most, and `deliverySignals.logic.ts`'s doctrine at lines 16-24 forbids zero-filling an unmeasured signal — a restore that invented `durationMs: 0` would fabricate evidence about the candidate's speech, which is the same class of mistake as fabricating a band). `savedAt` is `input.now ?? Date.now()`.

- **`serializeDraft`** is `JSON.stringify(d)`. Nothing else.

- **`parseDraft`** never throws. Wrap `JSON.parse` in `try { ... } catch { return null; }`. After parsing, return `null` unless ALL of these hold: the value is a non-null object, `v === DRAFT_VERSION`, `paperId === <arg>`, `skill === <arg>`. Then normalise missing containers to `{}`/`[]` so a partially-written draft still restores what it has. Comment: there is no migration path for this object on purpose — it is deleted on every successful submit (D-08), so a schema change simply orphans one sitting's unreadable draft, which is strictly better than carrying `progress.logic.ts`-style migration machinery for a value whose whole lifetime is one exam.

- **`restoreState`** rebuilds `spoken` as `SpokenAnswer` by adding `audioUri: null` back to each `DraftSpoken`. Pass `answers`/`texts`/`coverage`/`debate` through unchanged.

- **`markGraded`** returns `{ ...d, graded: d.graded.includes(taskId) ? d.graded : [...d.graded, taskId] }`. Never mutate.

- **`hasContent`** returns true if any of `answers`, `texts`, `spoken`, `coverage`, `debate` has at least one own key, or `graded.length > 0`. Comment: plan 07-02's mount effect uses this to avoid writing an empty draft over a real one before restore completes.

Then create `ealch-v2/src/services/examDraft.logic.test.ts` covering every item in `<behavior>` above. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device storage → app process | A previously written `exam-draft:*` AsyncStorage value is read back into exam state after a crash. The value is the user's own prior input, but the process that wrote it died, so the value may be truncated, corrupt, or written by an older build. |

Per RESEARCH.md's Security Domain section this phase crosses no auth, session, access-control, or cryptography boundary. Draft content is the same exam-response text that already travels to `grade-exam` over the network once graded, stored at the same (unencrypted) classification as every other AsyncStorage key in this app (`config.ts`, `analytics.ts`, `useProgress.ts`). No new data classification is introduced.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | `parseDraft()` in `examDraft.logic.ts` | mitigate | `JSON.parse` wrapped in try/catch returning `null`; `v`/`paperId`/`skill` all validated against the caller's expectations before the object is trusted; missing containers normalised to `{}`/`[]`. A malformed or foreign draft degrades to "no draft" rather than throwing inside an exam. Pinned by tests 5-8. |
| T-07-02 | Information Disclosure | `exam-draft:*` AsyncStorage entry | accept | Unencrypted at rest, same as every existing AsyncStorage key in this app. Contents are the candidate's own essay/transcript text on their own device; an attacker with the storage already has the app session. No PII beyond what the user typed. ASVS L1 does not require at-rest encryption for this classification. |
| T-07-03 | Information Disclosure | recorded-audio file path (`SpokenAnswer.audioUri`) | mitigate | `buildDraft()` drops `audioUri` entirely (D-09) — the draft never carries a filesystem path into persistent storage. Pinned by test 2. |
| T-07-04 | Repudiation | `graded: string[]` skip list | accept | A tampered skip list can only cause the user to skip grading their own answers. No privilege is gained and no other user is affected. `grade-exam`'s own `attemptAuthorized()` remains the server-side boundary. |
</threat_model>
