<two_constraints_that_decide_the_whole_method>
**1. A dev build can never display an exam paper, so BUG-02 cannot be verified on one.** Three facts compose: `ealch-v2/src/content/seed.json` carries no exam keys at all (papers live only in the published snapshot); `refreshFromRemote()` in `src/services/content.ts` opens with `if (__DEV__) return;`; and `initContent` calls `adoptedForLaunch(await readCache(), __DEV__)`, which returns null in dev. Both guards are deliberate — they exist so a dev build shows the hand-edited seed — and defeating them is the wrong move. The exam device-proof path is a **release build**. Verify these three facts still hold in the current code before building; if any has changed, say so in the summary rather than assuming.

**2. Editing `tts.ts` breaks Android TTS hot-reload in dev.** A Metro hot-reload after plan 07-04's edit leaves the device engine not-bound and silent, which is indistinguishable from a broken fix. A release build sidesteps this entirely — there is no Metro.

Both constraints point the same way: **one locally built release APK verifies both bugs.** A locally built release is signed with the debug keystore (`ealch-v2/android/app/build.gradle`: `release { signingConfig signingConfigs.debug }`), so `adb install -r` replaces the installed build with no data wipe.
</two_constraints_that_decide_the_whole_method>

  <what-built>
`app/exam-section.tsx` now checkpoints the candidate's answers to a dedicated `exam-draft:{paperId}:{skill}` AsyncStorage key: immediately on any committed answer (an MCQ selection, a finished recording, a coverage or debate result), 1500ms after typing stops, on backgrounding, and on unmount. On mount it reads that draft back and refills all five answer stores silently — no banner, no prompt. `submit()` writes the draft before requesting the first grade, skips any task already graded in the same interrupted sitting, records each grade as it lands, and deletes the draft once the section completes.

The recorded audio file path is deliberately NOT persisted — only the transcript, the measured delivery signals, and the "microphone was unavailable" flag. The STT cache file is not guaranteed to survive a process death, so persisting its path would promise a recovery the app cannot deliver.

  <what-built>
`tts.ts` now registers an `AppState` listener at module scope. Backgrounding calls `pauseForBackground()`; foregrounding calls `resumeFromForeground()`. The two playback paths deliberately differ:

- **ElevenLabs / `expo-audio`:** a true pause and resume from position. The pause does not bump the internal `generation` counter, so the finish callback that drives step-advance is still valid when playback resumes.
- **Device engine / `expo-speech`:** there is no resume-from-this-word API on either platform, so foregrounding restarts the current line from its beginning. Hearing a sentence twice is the accepted cost of never losing playback entirely.

Before this, a backgrounded app kept talking.
  </what-built>
