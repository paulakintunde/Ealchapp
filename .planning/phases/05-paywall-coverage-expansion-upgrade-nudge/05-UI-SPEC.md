# Phase 5 — UI Design Contract

> Visual and interaction contract for Phase 5 (Paywall Coverage Expansion & Upgrade Nudge). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Platform note:** Ealch is a React Native / Expo Router app, not a web app. There is no shadcn/Tailwind/component-registry ecosystem here — the project has its own in-house design system (`ealch-v2/src/theme`, `ealch-v2/src/components/{Type,Icon,ui}.tsx`). This UI-SPEC therefore documents that existing system where the template calls for a registry, and treats this phase as an **extension** of proven visual patterns (`PushBanner.tsx`, `paywall.tsx`, `den.tsx`'s row-lock tag), not a new design.

**Scope of this contract** (per 05-CONTEXT.md and 05-RESEARCH.md): contextual paywall copy (D-08), the generalized multi-kind banner slot shared by the upgrade nudge (D-11/D-12) and the reconciliation message (D-15/D-16/D-17), and the locked treatment for the four newly-gated drill screens (`flashcards.tsx`, `dictation.tsx`, `voiceflash.tsx`, `sentence.tsx`, per D-06/RESEARCH Pitfall 4). D-05's `setResume` fix is logic-only — no UI surface, confirmed below.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (no shadcn — React Native, not a web/Tailwind stack) |
| Preset | not applicable |
| Component library | In-house: `TX` (themed text, `src/components/Type.tsx`), `Press` (pressable + haptic cue, `src/components/ui.tsx`), `Icon` (custom SVG set, `src/components/Icon.tsx`), `FocusHeader` (`src/components/ui.tsx`) — all reused as-is, no new primitives needed this phase |
| Icon library | Custom inline SVG set, `src/components/Icon.tsx` (24×24 viewBox, stroke or fill). This phase reuses existing glyphs only: `lock`, `star`, `chevronRight`, `x`, `check`. **No new icon is required.** |
| Font | Instrument Sans (400/500/600/700, via `@expo-google-fonts/instrument-sans`) for all UI text; Instrument Serif (400 only, incl. italic) reserved for paywall display headlines — matches existing `paywall.tsx` usage, not a new pairing |
| Theming | Dynamic dark/light `Theme` object (`src/theme/palette.ts`, `useTheme()`), 4 selectable accent hues (Riviera/Corail/Champagne/Nuit). All colors below MUST be referenced via theme tokens (`t.acc`, `t.card2`, etc.), never hardcoded hex — matches 100% of existing code in the touched files |

Registry safety gate: **not applicable** — no shadcn, no third-party component registry in this stack.

## Spacing Scale

Declared values (must be multiples of 4), for any genuinely NEW layout this phase introduces (the banner's kind-specific rows, the paywall's `gate:examiner` explainer branch):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside the banner masthead row |
| sm | 8px | Compact gaps between banner badge and text block |
| md | 16px | Default padding for new paywall explainer content blocks |
| lg | 24px | Paywall screen horizontal padding (matches existing `ScrollView` `paddingHorizontal: 24`) |
| xl | 32px | Vertical gap above/below the `gate:examiner` explainer's icon badge |

**Exceptions (existing codebase idiom — do not "fix" these to the 4pt grid):** `PushBanner.tsx`'s card padding (`13`/`15`), `den.tsx`'s row padding (`14`/`16`) and gaps (`9`, `13`) are pre-existing, off-grid values baked into components this phase edits in place. When extending these components (adding a new `banner.kind` render branch, adding the lock tag to the four `*themes.tsx` browse screens), **match the surrounding file's existing spacing values exactly** rather than introducing a competing 4pt-perfect variant beside them — visual consistency with the immediate surrounding code wins over grid purity for values already shipping in production. New standalone blocks (the `gate:examiner` explainer) should use the 4pt scale above since they have no surrounding precedent to match.

## Typography

This phase does not introduce a new type scale — it reuses the project's existing `TX` role system (`src/components/type.logic.ts`). The 4 roles below are the ones this phase's touched surfaces actually use; do not introduce new roles or ad-hoc `size=` overrides beyond what's listed.

| Role (template row) | TX role | Size | Weight | Line Height | Used for |
|------|------|------|--------|-------------|----------|
| Label | `eyebrow` | 11px | semibold 600 (`font="bold"` or `"semi"`, `ls: 1.2–2.6`) | 1.3 | Banner masthead text (`EALCH`, `EALCH PREMIÈRE`, `ACCOUNT`); the `PREMIÈRE` lock tag reused on the 4 browse screens |
| Body | `label` | 13px | regular 400 (`font="sans"`, default) | 1.4 | Banner body copy (nudge/reconciliation message text) |
| Heading | `display` (size override 28) | 28px | regular (InstrumentSerif — see note) | ~1.15 | `paywall.tsx`'s `gate:examiner` explainer title — same size override the existing "already premium" success branch uses (`pwSuccessT`, line 185), not a new size |
| Display | `display` (default) | 34px | regular (InstrumentSerif) | 1.1 | `paywall.tsx`'s main sell-screen headline (`pwTitle` and all `gate:*` contextual headline variants) — unchanged from what ships today |

**Weight note:** exactly 2 weights are used by this phase's new/touched copy: **regular (400, Instrument Sans, `font="sans"`)** for all body/label copy, and **semibold (600, Instrument Sans, `font="semi"` or `"bold"`)** for masthead labels, lock tags, and CTA button text. Instrument Serif — used only for the two headline sizes above — ships in one weight; do not attempt to bold it. Visual emphasis on headlines comes from the serif+large-size pairing, not font-weight.

## Color

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `t.bg` | Screen background — paywall, the four drill screens' blank redirect placeholder |
| Secondary (30%) | `t.card` / `t.card2` | Paywall feature rows, plan-picker cards, the banner's own card shell (`t.card2`), the browse-screen row cards that gain a lock tag |
| Accent (10%) | `t.acc` / `t.accA(n)` | **Reserved for:** the paywall CTA button and its icon badges; the `upgradeNudge` banner's badge background and masthead label color (`t.accTx`); the `PREMIÈRE` lock tag background (`t.accA(12)`) and icon/text (`t.accTx`) reused on the 4 browse screens; the selected plan-picker row's border/gradient (unchanged, pre-existing) |
| Destructive | `t.danger` | **Not used anywhere in this phase's new UI.** Explicit decision: the reconciliation banner (D-17) is a "your access lapsed" notice, not an error or a destructive-action confirmation — using `t.danger`/red would misrepresent it as alarming when D-16 requires it to be non-blocking and calm. |

**New color decision this phase must lock in:** the `reconciliation` banner kind uses a **neutral badge**, not the accent badge the `speakReminder`/`upgradeNudge` kinds use — background `t.card2` with a `t.line(20)` border, icon/text in `t.txSubtle` — so it reads visually distinct from an upsell at a glance (an accent-branded badge reads as "buy something"; a neutral badge reads as "a status notice"). This is the one deliberate exception to "reuse the existing badge treatment unchanged."

## Copywriting Contract

### Required table

| Element | Copy |
|---------|------|
| Primary CTA | Reuse existing: `T.pwCta` ("Continue" / "Continuer") for the sell-state paywall; `T.pwCtaGuest` ("Sign in to subscribe") when signed out. No new CTA label needed — contextual variants change the headline/lead above the button, never the button label. |
| Empty state heading | Not applicable — this phase adds no new empty-data states. |
| Empty state body | Not applicable. |
| Error state | Reuse existing: `T.pwUnavailableT` / `T.pwUnavailableS` (purchases unavailable) — unchanged by this phase. |
| Destructive confirmation | None — no destructive action is introduced by this phase. |

### Phase-specific content (new strings needed)

**1. Paywall contextual copy, keyed on the existing `from` param's `gate:*` prefix (Pattern 3 / D-08).** Add these as new `strings.ts` key pairs (FR + EN), following the register of the existing `pwFeat*`/`pwLead` strings (plain, direct, no em dash, second person). `PAYWALL_COPY` falls back to today's generic `pwTitle`/`pwLead` for any `from` value that isn't one of the four keys below (`'home'`, `'settings'`, `'placement'`, `undefined`).

| `from` value | New headline (EN) | New lead (EN) |
|---|---|---|
| `gate:levels` | "Unlock A2 and beyond" | "Every level past A1, unlocked. Sons and A1 stay free forever." |
| `gate:coach` | "Unlimited coach conversations" | "Keep asking your coach after today's free questions run out." |
| `gate:roleplay` | "Unlimited role plays" | "Every scene, every day. Free covers one scenario a day." |
| `gate:examiner` | See dedicated explainer branch below — **do not** show this on the normal sell screen. |

**2. `gate:examiner` is a distinct THIRD paywall render branch, not a headline swap.** `entitlement.logic.ts` deliberately excludes `'examiner'` from `PREMIERE_FEATURES` — buying Première does not unlock exam papers. Showing the normal plan-picker under an exam-flavored headline would let a user pay for Première believing it includes exams. Resolution (closes RESEARCH's Open Question 1): reuse the exact layout shape of `paywall.tsx`'s existing "already premium" branch (lines 174–199: centered icon badge + serif headline at size 28 + one body line + one full-width CTA, no plan picker) with:
- Icon: `lock` (not `check`), in a neutral `t.txSubtle`-on-`t.line(10)` badge, not the accent-filled success badge — this is an explainer, not a success state.
- Headline (28px serif): "Exam papers are a separate pass"
- Body (`bodySm`, `t.txMuted`): "Première doesn't include TEF, TCF or DELF exam papers yet."
- CTA: single button, label "Got it", `onPress={() => router.back()}` — dismiss only, no purchase action, since no exam-tier purchase surface exists to sell today.
- Also add `from: 'gate:examiner'` to `exam.tsx`'s and `exam-paper.tsx`'s `router.push('/paywall', ...)` calls (currently pass no params at all — RESEARCH Code Examples), otherwise this branch can never trigger.

**3. Upgrade nudge banner copy (D-11/D-12), `banner.kind === 'upgradeNudge'`.** Fires when `roleplay.tsx` logs the day's first scenario attempt and that attempt just consumed `FREE_SCENARIOS_PER_DAY` (the "brushed the limit, not blocked yet" moment).
- Masthead label (eyebrow, `t.accTx`): reuse existing `T.pwTag` string ("EALCH PREMIÈRE").
- Body (label, `t.txSecondary`): "You used today's free role play. Go unlimited for more scenes."
- Press target: `router.push('/paywall', { params: { from: 'gate:roleplay' } })` — lands directly on the matching contextual headline from table 1 above, not the generic screen.
- No top-right meta (time) — that slot is unique to `speakReminder`; leave blank for this kind.

**4. Reconciliation banner copy (D-15/D-16/D-17), `banner.kind === 'reconciliation'`.** Fires as a second statement inside `useEntitlement.ts`'s existing `wasDowngraded` branch.
- Masthead label (eyebrow, `t.txSubtle`, neutral badge per Color section): "ACCOUNT" (FR: "COMPTE") — deliberately NOT "EALCH PREMIÈRE"; this is a status notice, not a sell.
- Body (label, `t.txSecondary`): "Your Première access has ended. Tap to check your subscription."
- Press target: `router.push('/settings')` — Settings already carries the Restore Purchases action (`restoreT`/`restoreDone`/`restoreNone` strings, already built in Phase 4); do not duplicate that flow inside the banner itself.
- Per D-17: this copy is intentionally generic about cause (no "cancelled" / "payment failed" / "expired" distinction) — do not add copy that speculates on the reason.

**5. Four newly-gated drill screens (`flashcards.tsx`, `dictation.tsx`, `voiceflash.tsx`, `sentence.tsx`) — no new copy.** These reuse the exact `lesson.tsx`/`narrated.tsx` render-time-redirect pattern verbatim: `trackEvent('gate_blocked', { feature: 'levels.all', from: '<screen-name>' })`, `router.replace({ pathname: '/paywall', params: { from: 'gate:levels' } })`, and a bare `<View style={{ flex: 1, backgroundColor: t.bg }} />` placeholder — no spinner, no lock icon, no text, matching the sub-frame duration of the existing redirect exactly. Do not design a new "locked" placeholder screen; that would be inconsistent with the two screens already shipping this exact pattern.

**6. Upstream browse-screen lock tag (`theme.tsx`'s step list, `flashthemes.tsx`, `dictationthemes.tsx`, `voicethemes.tsx`, `sentencethemes.tsx`) — UI-SPEC decision resolving RESEARCH Open Question 3.** The destination-screen redirect (#5) is the mandatory enforcement chokepoint and is sufficient on its own. This phase additionally requires the upstream browse row/step for a locked level to carry the **exact same lock tag `den.tsx` already renders** (lines 233–239: `Icon name="lock" size={11}`, `t.accA(12)` background pill, `t.accTx` text, `T.premLockTag` string — "PREMIÈRE"), so a free user sees the lock before tapping in, not after a tap-then-bounce round trip. Reuse the literal JSX/styling from `den.tsx`; do not invent a second lock-tag visual.

## Interaction Contract — Generalized Banner Slot (D-14)

Not part of the template's default sections, but required for this phase's checker/executor to build against a single shared shape:

| Property | `speakReminder` (existing, unchanged) | `upgradeNudge` (new) | `reconciliation` (new) |
|---|---|---|---|
| Badge background | `t.acc` | `t.acc` | `t.card2` + `t.line(20)` border (neutral — see Color) |
| Badge glyph | "E" wordmark (`TX font="serifI" role="titleLg"`, unchanged) | Same "E" wordmark — no icon swap, keep one consistent brand mark across all banner kinds | Same "E" wordmark, rendered in `t.txSubtle` instead of `t.accInk` to match the neutral badge |
| Masthead label | "EALCH" | "EALCH PREMIÈRE" | "ACCOUNT" / "COMPTE" |
| Top-right meta | Formatted time (`T.now` + `formatTime`) | none | none |
| Body copy | `T.bannerText` (unchanged) | Copywriting #3 above | Copywriting #4 above |
| Press action | `hideBanner(); router.push('/speak')` | `hideBanner(); router.push('/paywall', { params: { from: 'gate:roleplay' } })` | `hideBanner(); router.push('/settings')` |
| Auto-dismiss | 12000ms, set by `useAlarmWatcher.ts`'s own timer (unchanged) | **New:** 10000ms auto-hide if untapped, so a nudge never lingers indefinitely over active content (D-16's "non-blocking" spirit applies to both new kinds, not just reconciliation) | **New:** 10000ms auto-hide, same rationale |
| Slide animation | `Animated.timing`, 500ms, translateY -140→0 (unchanged) | Same, unchanged | Same, unchanged |
| Simultaneity | Exactly one banner visible at a time — guaranteed structurally by `banner: BannerState \| null` (a single Zustand field), not by app-level coordination logic | | |

**Frequency cap (D-13, Claude's Discretion — this is the proposed default):** `upgradeNudge` is capped at once per 24 hours regardless of how many times the roleplay trigger condition re-fires that day (a returning user who plays their one free scenario daily should not see the nudge every single day forever — cap it further if repeat-dismissal data suggests fatigue, but 24h is the phase's starting cadence, deliberately far more frequent than Phase 10's 3/year rating-prompt cap per D-13's explicit instruction). `reconciliation` has no frequency cap — it should reappear on every relevant screen transition until the user acts, since a lapsed subscription is a standing state, not a one-off event (do not silently suppress it after first shown).
