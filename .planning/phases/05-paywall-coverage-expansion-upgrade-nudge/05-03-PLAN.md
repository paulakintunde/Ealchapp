<objective>
Close the largest confirmed gap in the phase: `flashcards.tsx`, `dictation.tsx`, `voiceflash.tsx` and `sentence.tsx` currently render corpus items filtered only by theme and level, with **zero** reference to `hasFeature`, `FREE_BANDS` or any entitlement predicate (confirmed by direct grep in 05-RESEARCH.md). A free user reaches A2-level vocabulary, dictation, pronunciation and sentence-building drills through `theme.tsx` and the four `*themes.tsx` browse screens, entirely bypassing the "A2+ is Première" boundary that `den.tsx`, `lesson.tsx`, `narrated.tsx` and `placement.tsx` enforce for full lessons.

Purpose: PAY-02's success criterion is a gating rule "applied consistently across the catalogue". Today the rule is applied to lessons and not to drills over the same graded corpus. This plan is what makes the documented boundary true.

Output: four screens carrying the render-time gate, plus a wiring test that fails if any of them loses it.

Two deck shapes, one rule — this is why the gate is `drillDeckGate` and not a copy of `narrated.tsx`'s `unitBand` check:
- `theme.tsx` routes in with `?theme=&level=` — an explicit band, so the whole deck is gated and the screen redirects.
- The four `*themes.tsx` screens route in with `?theme=` only, and `flashcards.tsx` also accepts `?domain=&ctype=` and `?deck=new`, and `sentence.tsx` has a no-theme whole-corpus path. Those decks MIX bands, so a blanket redirect would wrongly wall off free content. The rule keeps the free-band items and only redirects when that filter empties a non-empty deck.
</objective>

```typescript
// ealch-v2/src/store/entitlement.logic.ts
export type LeveledItemLike = { level: string };
export function drillDeckGate<T extends LeveledItemLike>(
  raw: readonly T[],
  level: string | undefined,
  levelsAll: boolean,
): { items: T[]; locked: boolean };
//   explicit non-free `level`            → { items: [], locked: true }
//   mixed deck, not entitled             → { items: <FREE_BANDS only>, locked: items.length === 0 && raw.length > 0 }
//   entitled (or dev A2 unlock)          → { items: [...raw], locked: false }
//   raw = []                             → { items: [], locked: false }   (thin corpus, not a paywall)
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| route params (`?theme=&level=&domain=&ctype=&deck=`) → drill screen | Internal, developer-controlled strings produced by `theme.tsx`/`*themes.tsx`, plus deep links. Not user-typed free text. |
| bundled corpus → rendered deck | Corpus ships in the app binary. |
| device clock → entitlement expiry | Already mitigated by `guardedNow()` upstream; these screens read `useFeature`, which evaluates at `guardedNow()`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-10 | Tampering | The four new client-side drill gates | accept | **Not a security boundary.** Per 05-RESEARCH.md's Security Domain section (ASVS V4), the corpus ships bundled in the app binary, so a determined user can read any A2 item out of the bundle regardless of what this gate does. This plan closes a business-model and consistency gap, not a vulnerability. The genuine server-side access-control boundaries (Phase 3's coach quota, `startExamAttempt`'s `needs-exam-tier` refusal) are untouched by this phase and remain the enforcement for anything that actually costs money to serve. |
| T-05-11 | Spoofing | A deep link forging `?level=a1` on an A2 theme to reach gated items | mitigate | `drillDeckGate` does not trust the param as an allowlist: when the param names a free band it falls through to `freeBandItems`, which filters on each item's OWN `level` field from the corpus. A forged `level=a1` therefore yields only genuinely-a1 items, not the A2 deck. This is why the gate filters items rather than only branching on the param. |
| T-05-12 | Spoofing | A deep link with a garbage `?level=` value | mitigate | `drillLevelLocked` treats any band not in `FREE_BANDS` as locked, including unrecognised strings, so a junk value fails closed rather than open. Pinned by Plan 01's `drillLevelLocked('not-a-band', false) === true` test. |
| T-05-13 | Information disclosure | Gated content painted for one frame before the redirect | mitigate | The `if (bandLocked) return <View/>` short-circuit runs synchronously in the same render pass that schedules the redirect effect, so no deck JSX is ever reached. This is the shape `lesson.tsx`/`narrated.tsx` already ship, and Task 2's wiring test asserts the exact placeholder string in all four files. |
| T-05-14 | Denial of service | `freeBandItems` filtering a large domain deck | accept | One `Array.filter` over an already-materialised slice, at the same call site that already runs `dedupeByFr` and a full band sort over the same array. |
| T-05-15 | Elevation of privilege | Gate silently blocking a free user out of free content | mitigate | The failure mode that matters most for a paying-adjacent screen is the false positive. `drillDeckGate` returns `locked: false` for an empty `raw` (a thin corpus is an empty state, not a paywall) and returns the free-band subset rather than redirecting for a mixed deck. Both are pinned by Plan 01's unit tests and re-checked at Plan 07's device checkpoint. |
</threat_model>
