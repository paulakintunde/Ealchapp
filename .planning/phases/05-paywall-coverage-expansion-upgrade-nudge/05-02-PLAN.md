<objective>
Close the two lock-VISIBILITY gaps that sit around the real enforcement chokepoints: the `setResume` leak that writes a locked lesson into the "continue where you left off" pointer (the real bug behind D-05, per 05-RESEARCH.md Pitfall 2 — there is no render flash to fix, the synchronous `if (bandLocked) return <blank/>` already prevents it), and the missing upstream lock pill on the five browse screens that route into the four drill screens (UI-SPEC Copywriting item 6, resolving 05-RESEARCH.md Open Question 3).

This plan is visibility only; it adds no enforcement and removes none.

Output: two one-condition bug fixes, five browse screens carrying `den.tsx`'s existing lock pill verbatim, and one wiring test file.

Scope note: this plan runs in Wave 1 alongside Plan 01 because it shares no files with it and needs no new strings — `T.premLockTag` ("PREMIÈRE") already exists and already ships in `den.tsx`.
