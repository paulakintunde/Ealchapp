The config-merge pattern for touching an already-seeded live `system_config` row —
`ealch-admin/scripts/apply-tts-quota-schema.ts` lines 29-41:

```typescript
await c.query(
  `update public.system_config set config = config || $1::jsonb where id = 'active'`,

```
`||` is additive — it preserves every existing key. The `insert ... on conflict do
nothing` in `schema.sql` never re-runs against an existing row, so this is the only
way a config key lands live.

`ealch-admin/scripts/env.ts` exports `describeTarget()` and `isRemoteTarget()`.
`import './env'` must be the FIRST import in any standalone script.

The client's own defaults (`ealch-v2/src/services/config.ts`): `examGateOn: false`,
`examFreePapers: 1`. The client reads config on launch and on foreground
(`refreshConfig()`), so a flip needs an app foreground cycle — not a rebuild — to be
seen on the device.

The decision the flip activates (`ealch-v2/src/utils/examGate.logic.ts`):
```typescript
if (!gateOn) return { allowed: true };
if (entitled) return { allowed: true };
if (paperNo <= Math.max(0, Math.floor(freePapers))) return { allowed: true };
return { allowed: false, reason: 'needs-exam-tier' };
```
With `examGateOn: true` and `examFreePapers: 1`, an unentitled candidate keeps paper 1
of each format and loses papers 2+.

The row `start-exam-attempt` writes (`public.exam_attempts`, created in 04-02):
`(user_id, paper_id, skill)` PK, plus `started_at`, `expires_at`, `gate_on`,
`entitled`, `paper_no`, `mode`.

D-06's window, as implemented in `ealch-v2/src/utils/examAttempt.logic.ts`:
`expires_at = started_at + (clampTimingS(section.timingS) + 3600) * 1000 ms`.
`section.timingS` comes from `content_exam_papers.sections` — a jsonb array whose
objects carry camelCase `skill` and `timingS`.

The exact predicate `grade-exam` uses (04-06): a select on `exam_attempts` filtered by
`user_id`, `paper_id`, `skill` and `expires_at > <the function's own now>`.
