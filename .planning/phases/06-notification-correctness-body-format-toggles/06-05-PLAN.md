  <what-built>
Three notification kinds now schedule as real device notifications through one service, each with its own identifier:

- **daily** — `daily-reminder`, fires at the alarm time set in Settings (unchanged behaviour, but its body is now fully substituted and its scheduling no longer wipes the other kinds).
- **report** — `report-session`, one shot, fires 3 minutes after any practice session is logged, when the report toggle is on.
- **nudge** — `nudge-mon` and `nudge-thu`, weekly, Monday and Thursday at 18:30, generic encouraging copy.

Turning a toggle off cancels only that kind's identifiers. Reopening the app re-arms the schedule from the toggles and drops any orphan daily reminder left by a pre-Phase-6 build.
  </what-built>
  <how-to-verify>
**Setup.** App running on the device (Task 1 left it there). Open Settings > Practice reminders. If a convenience deep link helps: `adb shell am start -a android.intent.action.VIEW -d "ealch://settings"` (scheme is `ealch`). Grant the OS notification permission the first time a toggle asks.

**Check A — body text has no leftovers (NOTIFY-02, the phase's headline bug).**
1. Turn the **Evening reminder** toggle ON, accept the permission prompt.
2. Set the alarm time to two minutes from now.
3. Lock the phone and wait.
4. **Expect:** a notification titled "Ealch" whose body reads as a complete sentence with a real time and the coach's name, e.g. `Your 7:04 PM session is waiting: Au Café, 4 min with Brix.` (FR: `Votre séance de 19:04 vous attend : Au Café, 4 min avec Brix.`)
5. **Fail if:** the body contains a literal `{t}` or `{name}`, or the sentence is missing its last words.

**Check B — one toggle off does not silence the others (NOTIFY-01, the pitfall this phase was designed around).**
1. With Evening reminder still ON, turn **Confidence nudges** ON, then turn it back OFF.
2. Set the alarm time to two minutes from now again.
3. Lock the phone and wait.
4. **Expect:** the daily reminder still arrives.
5. **Fail if:** nothing arrives — that means cancelling one kind took the others with it.

**Check C — the report fires after a session, and only when its toggle is on (NOTIFY-01, D-04).**
1. Ensure **Daily report** is ON. Confirm its sub-label says the report comes right after the session, not "each evening".
2. Open any lesson, flashcard deck or dictation and finish it so the session is logged. Leave the app (home button).
3. Wait about 3 minutes.
4. **Expect:** a notification reading `Your report is ready: see how your session with Brix went.` (FR: `Votre rapport est prêt : découvrez comment s'est passée votre séance avec Brix.`) — again with no literal `{name}`.
5. Now turn **Daily report** OFF, finish another session, and wait 5 minutes.
6. **Expect:** no report notification arrives.

**Check D — the nudge cadence (optional but preferred; skip only if changing the device clock is not acceptable).**
1. Turn **Confidence nudges** OFF. Set the device date/time to the next Monday, 18:28.
2. Turn **Confidence nudges** ON (this schedules against the new clock).
3. Wait past 18:30.
4. **Expect:** `Two minutes is enough to make progress: Brix is ready for a quick micro-challenge.` (FR: `Deux minutes suffisent pour progresser : Brix vous attend pour un micro-défi.`)
5. Restore the device clock to automatic afterwards.

**Check E — no duplicate daily after an upgrade (optional; only if a pre-Phase-6 build is still installed or easy to reinstall).**
1. On the old build, enable the evening reminder.
2. Install this build over it, open the app once, then set the alarm to two minutes out.
3. **Expect:** exactly ONE daily notification arrives, not two.

**Known limitation, expected and in scope:** tapping any of these notifications opens the app to its default screen rather than the session it advertised. That is Phase 17 (NOTIFY-03) and is explicitly out of scope here — it is not a defect to report against this phase.
